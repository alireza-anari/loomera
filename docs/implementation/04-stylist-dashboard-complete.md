# مرحله 4: داشبورد کامل آرایشگر

## هدف
این مرحله داشبورد آرایشگر را از حالت ساده به یک لایه عملیاتی کامل‌تر تبدیل می‌کند، بدون بازنویسی UI فعلی. تمرکز روی backend، context سالن فعال، دسترسی‌های هر سالن، جلوگیری از تداخل چندسالن، مرخصی، مالی آرایشگر و آماده‌سازی پروفایل حرفه‌ای است.

## اصول اجرا
- هیچ template یا Tailwind بازنویسی نشد.
- ساختار قدیمی `Stylist`, `StylistSchedule`, `StylistTimeOff`, `JobDetails` حفظ شد.
- لایه جدید روی `SalonMembership` و `StaffDashboardPermission` سوار شد.
- دسترسی‌ها و context سالن فعال در backend enforce شدند.
- داده‌های قبلی حذف یا reset نشدند.

## تغییرات اصلی

### 1. Context سالن فعال آرایشگر
سرویس `resolve_stylist_dashboard_context` اضافه شد و موارد زیر را برمی‌گرداند:
- آرایشگر
- سالن فعال
- عضویت فعال
- سطح دسترسی همان عضویت
- همه عضویت‌های فعال آرایشگر

اگر آرایشگر چند سالن داشته باشد، سالن انتخاب‌شده از session خوانده می‌شود و اگر وجود نداشته باشد، اولین عضویت فعال انتخاب می‌شود.

### 2. دسترسی‌های داشبورد آرایشگر
Viewهای آرایشگر اکنون به `StaffDashboardPermission` توجه می‌کنند:
- اجرای نوبت
- مشاهده مالی خود
- درخواست پرداخت
- مشاهده/ثبت مشتری خود
- مشاهده شماره تماس مشتری
- مدیریت برنامه کاری
- درخواست مرخصی
- مدیریت نمونه‌کار

### 3. جلوگیری از تداخل چندسالن
سرویس `validate_stylist_time_window` اضافه شد و هنگام ثبت برنامه کاری یا رزرو دستی آرایشگر این موارد را بررسی می‌کند:
- برنامه کاری موجود در همه سالن‌ها
- مرخصی ثبت‌شده
- درخواست مرخصی در انتظار/تأییدشده
- نوبت‌های فعال در همه سالن‌ها

### 4. درخواست مرخصی
مدل `StaffLeaveRequest` اضافه شد. آرایشگر به جای ثبت مستقیم مرخصی، درخواست ثبت می‌کند. اگر دسترسی `can_manage_own_schedule` داشته باشد، درخواست به صورت خودکار تأیید و `StylistTimeOff` ساخته می‌شود.

### 5. مالی آرایشگر و درخواست پرداخت
داشبورد مالی آرایشگر به `StaffEarning` و `StaffPayoutRequest` وصل شد. endpoint جدید زیر اضافه شد:

```text
POST /dashboards/stylist/finance/request-payout/
```

این endpoint مطالبات قابل پرداخت آرایشگر را به یک درخواست پرداخت تبدیل می‌کند.

### 6. پروفایل حرفه‌ای آرایشگر
فیلدهای جدیدی به `Stylist` اضافه شد:
- نام نمایشی حرفه‌ای
- سال شروع فعالیت
- وضعیت نمایش عمومی
- متخصص تأییدشده
- یادداشت سیستمی رزومه

فرم پروفایل فعلی بدون تغییر UI بنیادی، این فیلدها را پشتیبانی می‌کند.

### 7. نمونه‌کارها
مدل `WorkSamples` با metadata لازم برای پروفایل حرفه‌ای و کنترل محتوا توسعه داده شد:
- سالن مرتبط
- نوبت مرتبط
- عمومی/خصوصی
- نمونه‌کار تأییدشده
- وضعیت رضایت مشتری
- وضعیت بررسی
