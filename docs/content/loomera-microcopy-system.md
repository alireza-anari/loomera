# Loomera Microcopy System

> Version: 1.0  
> Brand: Loomera  
> Purpose: Source-ready microcopy system for product UI, transactional flows, notifications, and support.

---

## 1) Purpose

This document turns the Loomera Brand Voice Guide into executable product copy.
It is designed for use by:
- product designers
- content designers
- frontend teams
- support teams
- marketing teams working inside product surfaces

This system should be used for:
- navigation labels
- buttons and CTAs
- forms and helper text
- empty states
- error states
- booking flow
- checkout and payment
- notifications and reminders
- account and profile areas
- support macros and help center intros

---

## 2) Microcopy Principles

Every Loomera microcopy line should aim to do at least one of these well:
- clarify
- reassure
- guide

### Golden Rules
1. Be clear before being clever.
2. Keep the line short, but complete.
3. Reduce user effort.
4. Reassure in sensitive moments.
5. Never sound pushy or overly promotional.
6. Avoid cliché beauty language.
7. Keep the brand calm, refined, and human.

## 3) Writing Pattern Library

### A. Action Pattern
Use for buttons, menus, next steps.

**Formula:**
`Action + object`

Examples:
- رزرو نوبت
- انتخاب زمان
- مشاهده جزئیات
- تکمیل پروفایل

### B. Reassurance Pattern
Use for payment, booking, trust, and uncertainty-reduction.

**Formula:**
`Clear state + short reassurance`

Examples:
- پرداخت کامل نشد. مبلغی کسر نشده است.
- جزئیات رزرو قبل از پرداخت نهایی نمایش داده می‌شود.
- هر زمان خواستید می‌توانید زمان دیگری انتخاب کنید.

### C. Form Guidance Pattern
Use for field help and inline instructions.

**Formula:**
`What is needed + useful constraint`

Examples:
- شماره موبایل را با فرمت درست وارد کنید.
- نام و نام خانوادگی را مطابق اطلاعات حساب وارد کنید.
- این نام فقط برای نمایش در پروفایل استفاده می‌شود.

### D. Empty State Pattern
Use when no content, no results, or no history exists.

**Formula:**
`What happened + what the user can do next`

Examples:
- نتیجه‌ای با این فیلترها پیدا نشد. می‌توانید فیلترها را تغییر دهید.
- هنوز نوبتی ثبت نکرده‌اید. خدمات را ببینید و زمان مناسب خود را انتخاب کنید.

### E. Error Pattern
Use when action fails.

**Formula:**
`What happened + impact + next step`

Examples:
- پرداخت کامل نشد. مبلغی کسر نشده است. لطفاً دوباره تلاش کنید.
- اتصال برقرار نشد. لطفاً چند لحظه دیگر دوباره تلاش کنید.

### F. Success Pattern
Use when an action is completed.

**Formula:**
`Success state + useful next detail`

Examples:
- نوبت شما ثبت شد.
- پرداخت با موفقیت انجام شد و رزرو شما نهایی شد.
- اطلاعات پروفایل ذخیره شد.

## 4) Component-Level Rules

### Buttons
- Keep to 1–3 words where possible.
- Start with a verb when the action matters.
- Avoid vague labels like “شروع تجربه”.

Preferred:
- ادامه
- بازگشت
- رزرو نوبت
- مشاهده جزئیات
- تأیید و ادامه

Avoid:
- بزن بریم
- امتحانش کن
- شروع تجربه
- شگفت‌زده شو

### Labels
- Use familiar words.
- Do not be decorative.
- Labels should identify, not persuade.

Preferred:
- نام و نام خانوادگی
- شماره موبایل
- زمان رزرو
- روش پرداخت

### Helper Text
- Should explain what is needed.
- Keep to one sentence.
- Avoid repeating the field label.

Preferred:
- کد تأیید به این شماره ارسال می‌شود.
- این اطلاعات فقط برای هماهنگی رزرو استفاده می‌شود.

### Placeholder Text
- Use examples only when needed.
- Do not use placeholders as a substitute for labels.

Preferred:
- مثال: ۰۹۱۲۳۴۵۶۷۸۹
- نام سالن، خدمت یا متخصص

### Status Labels
- Must be short and scannable.
- Use consistent naming.

Preferred:
- تأیید شد
- در انتظار
- لغو شد
- انجام شد

### Toasts / Snackbars
- Short and state-led.
- Use for non-critical feedback.

Examples:
- تغییرات ذخیره شد.
- لینک کپی شد.
- اعلان‌ها به‌روزرسانی شد.

### Modals
- Title should state the decision.
- Body should explain consequence.
- CTA should be explicit.

## 17) Error Message Library

### Generic Connectivity
- اتصال برقرار نشد. لطفاً چند لحظه دیگر دوباره تلاش کنید.
- دسترسی به اطلاعات ممکن نشد. لطفاً دوباره تلاش کنید.

### Form Validation
- این فیلد را کامل کنید.
- شماره موبایل را با فرمت درست وارد کنید.
- کد تأیید معتبر نیست.
- ایمیل را با فرمت درست وارد کنید.

### Booking Errors
- این زمان دیگر در دسترس نیست. لطفاً زمان دیگری انتخاب کنید.
- رزرو کامل نشد. جزئیات را بررسی و دوباره تلاش کنید.
- امکان نهایی‌سازی این رزرو در حال حاضر وجود ندارد.

### Payment Errors
- پرداخت کامل نشد. مبلغی کسر نشده است. لطفاً دوباره تلاش کنید.
- ارتباط با درگاه پرداخت برقرار نشد. دوباره تلاش کنید.
- این پرداخت تأیید نشد. لطفاً روش دیگری را امتحان کنید.

### Account Errors
- ورود انجام نشد. لطفاً دوباره تلاش کنید.
- امکان ذخیره تغییرات وجود نداشت. دوباره تلاش کنید.
- جلسه شما منقضی شده است. لطفاً دوباره وارد شوید.

### Permissions / Access Errors
- دسترسی به این بخش برای شما فعال نیست.
- برای ادامه، ابتدا وارد حساب خود شوید.

### Error Tone Rules
- never blame the user
- never expose raw technical language unless needed
- always offer an action when possible

## 21) Copy QA Checklist

Before shipping any Loomera microcopy, check:

### Clarity
- آیا کاربر سریع می‌فهمد این متن چه می‌گوید؟
- آیا قدم بعدی روشن است؟

### Tone
- آیا متن آرام، محترمانه و refined است؟
- آیا بیش‌ازحد تبلیغاتی یا خیلی خشک نیست؟

### Usability
- آیا متن کوتاه‌تر هم می‌تواند باشد بدون از دست رفتن معنا؟
- آیا برای UI بیش‌ازحد طولانی نیست؟

### Trust
- آیا متن ابهام را کم می‌کند؟
- آیا در لحظه‌های حساس reassuring است؟

### Brand Fit
- آیا این متن می‌توانست متعلق به هر برند دیگری باشد؟
- آیا از clichéهای beauty دور مانده است؟
